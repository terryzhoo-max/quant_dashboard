# 波动率自适应仓位上限 · 设计与校准记录 (Vol Overlay V2)

> 日期: 2026-10-22 · 代码: `services/vol_regime.py`、`services/portfolio_vol.py`
> 复现: `python -m strategies.vol_overlay_calibration --grid`

## 1. 背景: V1 为什么等于没有

| 问题 | 证据 | 后果 |
|---|---|---|
| 从未运行 | `refresh_vol_cache()` 无任何调用方 | 系数恒为 1.0 |
| 管不到总仓位 | 只乘在子策略 `get_position_cap()` 上 | 决定"明日计划"的 AIAE cap 不受影响 |
| VIX 只有文案 | "Cap×0.75 / ×0.5" 只出现在指令文字里 | 显示降级, 实际未降 |
| 数据缺失 fail-neutral | 缺数据时系数 = 1.0 | 与 AIAE 的 fail-closed 原则矛盾 |

## 2. 校准方法 (时点安全)

- t 日收盘计算系数, t+1 日按 `系数 × 基础仓位` 持有; `compute_vol_factor_frame()` 第 t 行只用 ≤t 的数据 (有单测验证前缀不变性)
- **对照组 = 平均仓位相同的固定仓位**。只和满仓比会得到"降仓降低了回撤"的伪结论
- 现金年化 1.5%, 调仓成本 5bp/单位仓位变化
- 样本: 沪深300 2015-07~2026-09, 中证1000 / 创业板指 / 中证红利 2021-07~2026-09 (本地数据可得范围)

## 3. 结论

### 3.1 连续波动择时在 A 股无效 (V2 草案被否决)

"指数波动高就降仓、低就加仓"(系数 = (基准/当前)^α, 上限 1.1):
**48 组参数 (α × λ × 窗口 × 下限 × 迟滞) 在三个指数上全部跑输对照组**, 平均 ΔSharpe -0.06~-0.19, 最大回撤更深 4~9pp, 年换手 0.6~2.0。

| 变体 | 平均 ΔSharpe | 最差 ΔSharpe | 平均 ΔMaxDD | 年换手 |
|---|---|---|---|---|
| 连续择时 (触发线 1.0×) | -0.08 ~ -0.15 | -0.17 ~ -0.28 | -3.6 ~ -6.0pp | 1.5~2.5 |
| 波动+趋势 (跌破均线才刹) | -0.04 ~ -0.16 | -0.08 ~ -0.27 | -0.9 ~ -5.8pp | 0.5~3.2 |
| 指数回撤分级刹车 | -0.04 | -0.14 | -2.2pp | 4.0 |
| 纯趋势 MA60 (跌破降至 60%) | +0.03 | -0.19 | +1.5pp | 6.0 |
| 下行波动刹车 | -0.003 ~ -0.04 | -0.01 ~ -0.10 | -0.1 ~ -2.2pp | 0.1~0.8 |
| **尾部刹车 2.0× / α=0.5 (采用)** | **-0.004** | **-0.024** | **-0.3pp** | **0.18** |
| 尾部刹车 2.5× | +0.005 | -0.001 | -0.1pp | 0.07 |

纯趋势 MA60 是唯一平均为正的变体, 但在单个指数上最差 -0.19、年换手 6 次, 不稳健, 未采用。

原因: A 股的高波动集中在底部与 V 型反弹期 (2015-16、2018 末、2024-02、2024-09), 连续降仓系统性错过反弹。
网格呈单调关系: 干预越少越好。

### 3.2 采用: 尾部保险刹车

- `系数 = clamp((2.0 × 基准 / 当前波动)^0.5, 0.5, 1.0)`; 当前波动 < 2 倍自适应基准时系数恒为 1
- 波动估计 = max(EWMA λ=0.94, 60 日实现波动); 基准 = 3 年滚动中位数 (夹 12%~30%)
- 回测成本 ≈ 0 (ΔSharpe -0.004), 平时完全不动
- **选 2.0× 而非 2.5× 的理由不是夏普 (两者差异在噪声内), 而是危机覆盖**:
  - 2.0× 触发: 2015 股灾 (0.73)、2016 熔断 (0.88)、2018-10、2020-02 疫情、2024-02 微盘股流动性危机 (中证1000 0.88)、2025-04
  - 2.5× 漏掉 2016 熔断大部分、2018-10、2020-02、2024-02
  - 两者都会在 2024-09 的"上涨型高波动"误触发, 这是已知代价
- 定位是保险, 不是信号: **没有证据表明它提升收益, 也没有证据表明它有害**

### 3.3 数据质量处理

- 本地 ETF 收盘价未复权: 芯片ETF (159995) 单日对数收益 -0.70, 半导体设备ETF (159516) -0.77 (份额拆分)
- 剔除 |日对数收益| > 0.21 的跳变 (20cm 板 + 余量), 否则波动被严重高估 (芯片ETF 85% vs 真实 49%, 半导体设备ETF 115% vs 54%)
- 数据过期 > 10 个日历日 → 系数 ≤ 0.80; 从未算出 → 0.80 (fail-conservative); 显式关闭 → 1.0

## 4. 组合层波动预算 (按持仓结构, 非择时)

用 250 日等权窗口 (慢变量) 估计每个持仓的波动与相关性, 反映"持仓结构"而不是短期情绪:

- 最大权益仓位 = 目标波动 / 当前结构满仓时的波动 (默认目标 15%, 在 `vol_targeting.portfolio.target_vol` 设置)
- 单票上限 = min(静态上限, k/σ, 跌停跳空上限); 个股 k=3%, ETF k=8%; 20cm 板两个跌停 ≤ 账户 2% → 单票 ≤ 5.6%
- 有效独立押注数 = 分散比率² = (Σwσ/σp)²

2026-10-15 持仓 (17 只, 其中 8 只本地无行情用代理波动 60%):

| 指标 | 数值 |
|---|---|
| 组合年化波动 | 44.4% |
| 平均两两相关 | 0.60 |
| 有效独立押注数 | 1.48 |
| 当前权益仓位 | 98.3% |
| 目标 12% / 15% / 18% / 22% / 25% / 30% 对应最大仓位 | 27% / 33% / 40% / 49% / 55% / 66% |
| 超单票波动上限的持仓 | 安集 14.9%→4.7%, 沪电 9.3%→5.0%, 胜宏 7.9%→5.0%, 中芯 7.4%→5.6%, 科创50ETF 20.9%→18.9% |

合规规则 `vol_budget` 默认为软警告; 在 `strategy_runtime.json` 中把 `vol_targeting.portfolio.enforce_in_compliance` 设为 `true` 后升级为硬阻断。目标波动是个人风险偏好, 应先在投资政策中确认再开启硬阻断。

## 6. 已知局限

- 指数样本短 (中证1000/创业板 仅 5 年), 结论需在服务器长数据上用脚本复核
- 8 只个股本地无行情, 组合波动使用代理值; 服务器同步行情后会自动改用真实数据
- 组合层未包含现金类资产的负相关对冲效果 (目前持仓中没有)

## 7. 决策页面板的机构分析 (2026-10-22 v2)

| 模块 | 方法 | 2026-10-15 持仓读数 |
|---|---|---|
| 执行前后 | 同一协方差矩阵下比较当前与草案; VaR/ES 为正态近似 (低估肥尾) | 20日95% ES ¥38.2万 → ¥12.9万 |
| 压力情景 | β 线性冲击 (β 用 250 日估计, 缺行情取同类中位数) | 科创50 -40%: -¥63.7万 (-43%) → -¥21.9万 |
| 草案选择 | 同时算等比缩放与最小换手; 最小换手需少交易 ≥15% 才推荐 | 最小换手仅省 2.7%, 但前三风险占比 43%→68%, 推荐等比缩放 |
| 风险预算再利用 | 目标波动约束下的二次方程闭式解; 相关性按 max(样本, 0.3) 压力假设 | 主题 29% + 红利低波 33% = 总仓位 62%, 组合波动仍为 15% |
| 流动性 | 20 日成交额中位数, 10% 参与率 | 单笔最多占成交额 0.02%, 不构成约束 |
| 估计区间 | 代理波动 ±25% | 组合波动 41%–48% |

关键结论: 持仓平均相关 0.6, "卖哪只"几乎不改变所需换手, 真正的决策是"留多少主题风险"以及"腾出的风险预算给谁"。
红利低波 2026 年与科创50 的样本相关为 -0.38 (127 日), 这是风格轮动期的读数, 不作为定规模依据。

## 8. V3 生产化重构 (2026-10-23)

### 8.1 逻辑架构

`compute_portfolio_vol` 从一个 380 行的函数拆成纯函数流水线, 每段可单测、可替换, 对外 API 与返回字段完全向后兼容 (只增不删):

| 阶段 | 函数 | 职责 |
|---|---|---|
| ① 输入 | `_load_inputs` | 持仓 → 占账户总资产的权重 |
| ② 风险模型 | `_build_risk_model` | 收益面板 / 波动 / 收缩相关 / 协方差 / β / 每只的最后行情日 |
| ③ 约束 | `_constraints` | 单票上限 + 目标波动 → 最大权益仓位 |
| ④ 再平衡 | `_rebalance` | 等比缩放 vs 最小换手, 按规则选推荐草案 |
| ⑤ 分析 | `_historical_replay` `_stress` `_diversifiers` `_liquidity_and_plan` | 回放 / 压力 / 再配置 / 流动性 |
| ⑥ 视图 | `build_decision_view` → `_verdict` | 三层约束 + 单票超限 → 结论 |

### 8.2 新增

| 项 | 说明 |
|---|---|
| 历史回放 | 用当前权重回放过去 250 日: 非参数 VaR/ES、最差单日、最大回撤、净值路径 (当前 vs 草案)。缺口用 β×科创50 填补并披露占比。同时给出"历史 ES ÷ 正态 ES"肥尾倍数, >1.15 时进入使用须知 |
| 风险归因分桶 | 科创 20cm / 创业 20cm / 主板 10cm / ETF 的权重、风险贡献、风险/权重比 |
| 单票超限独立判定 | 总仓位在预算内但有持仓超单票上限时, 结论升级为"需处理", 给出超额金额 (V2 会显示"在预算内") |
| 行情新鲜度 | 每只持仓的最后行情日; 过期行情计入数据质量与 status, 不静默使用; 持仓快照 >3 天提示重新导入 |
| 审计元数据 | `meta.schema / fingerprint / computed_at / elapsed_ms / cache` |
| 结果缓存 | 指纹 = 持仓 + 参数 + 相关行情文件 mtime + 估值日; 任何输入变化自动失效; `?refresh=true` 强制重算 |
| 行情读取 | 每个 parquet 按 mtime 只读一次, close 与 amount 共用 (V2 每次请求读两遍); 支持 `gem_` 前缀副本 (黄金/货币 ETF) |
| 一致性修正 | 跳空情景的连续跌停天数跟随 `gap_limit_days` (V2 写死 2 天); ETF 冲击可配 `gap_shock_etf`; 最小换手循环上界随步长计算 |

新参数 (均有默认值, 可在 `vol_targeting.portfolio` 覆盖): `max_price_age_days=7`, `hs_window=250`, `gap_shock_etf=-0.10`, `cache_ttl_seconds=300`。

### 8.3 视觉架构

一屏只回答一个问题, 由粗到细:

1. **风险条** (始终可见): 结论徽标 + 指令 + 6 个读数 (有效上限 / 实际仓位 / 组合波动 / 独立押注 / 一年回放最大回撤 / 1 日 ES) + 行情日、持仓日、计算时间、重算按钮
2. **上限标尺** (始终可见): 一根 0–100% 轴, 安全区 / 实际仓位 / 超出部分斜纹 / 每层约束标记 (同值合并), 右侧为瀑布图例并高亮最严约束
3. **页签**: 概览 (分桶 + 约束读数) · 风险归因 (权重 vs 风险双条, 可排序) · 尾部与情景 (回放净值曲线 + 损失度量 + 压力) · 执行草案 (两方案对比 + 逐笔构成: 压上限 vs 降总仓位 + 再配置) · 方法与数据 (须知 / 数据质量 / 审计)

工程: 纯渲染函数 + 事件委托 (无内联 onclick); 刷新失败保留上次结果; 页签可键盘切换 (←/→/Home/End); 状态色只表达风险严重度, 不表达涨跌; 数字等宽; `prefers-reduced-motion` 关闭动画; 390px 宽无横向溢出。

# AlphaCore 生产就绪检查修复设计

日期：2026-10-13

## 目标

修复 `engines/production_check.py` 的三类可信度问题：

- 当前 AIAE 参数版本为 5.2，但检查器硬编码要求 5.0；
- 前端一致性通过搜索 `22.8`、`24%` 等显示文本判断，和真实运行契约无关；
- 检查失败时只打印 `NOT READY`，进程仍可能以退出码 0 结束，自动化无法阻断部署。

## 方案

采用分层检查，不改变现有业务引擎：

1. **代码就绪检查**：验证引擎可导入、V5 参数结构有效、信号边界与仓位矩阵正确、前端默认阈值与后端参数一致。
2. **数据就绪检查**：验证服务器本地历史数据与回测产物；仅完整模式执行。
3. **CLI 结果契约**：`main()` 返回明确退出码；存在失败返回 1，仅警告或全部通过返回 0。
4. **CI 模式**：`--code-only` 跳过未纳入 Git 的生产数据湖检查，供 GitHub Actions 使用。

## 前端一致性契约

不再检查页面是否出现某个展示数字。改为验证：

- `decision.html` 确实加载 `static/js/decision/hub_core.js`；
- `hub_core.js` 的 `_DEFAULT_REGIME_THRESHOLDS` 可解析；
- 解析结果与 `engines.aiae_params.V5_REGIME_THRESHOLDS` 完全一致。

后端下发值仍是主路径，前端默认值只承担接口异常时的安全回退。

## 测试

- 新增专项测试，先复现版本误判、前端误判和错误退出码；
- 验证 `--code-only` 不运行数据检查；
- 运行生产检查两种模式；
- 运行完整非集成测试集，确认无回归。

## 非目标

- 不修改 AIAE 策略参数；
- 不修复本轮审计发现的其他安全、合规或静态检查问题；
- 不要求 CI 拥有服务器运行时数据湖。
